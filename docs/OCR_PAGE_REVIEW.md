## 逐页流程

文稿页的“逐页核对 / 纠错识别文字”列出所有活动页，包括空文字、旧识别及四角待核对页。选择页面后可对照预览修改本页文字，查看未保存状态并复制当前草稿。整本复制读取已保存页面，复制不代表保存。

界面状态保存时可能生成私有生命周期快照，明确放弃也不删除已经生成的快照；页面内容仍需明确保存才生效。容量预检、故障和隐私边界见 [OCR_BYTE_BUDGET_FIX.md](OCR_BYTE_BUDGET_FIX.md)。

纠错复用现有编辑器的保存、保存并下一页、末页返回及恢复记录流程；不会额外要求一次 OCR 确认。输入回调绑定文稿、草稿对象、编辑会话和界面代次，拒绝旧页面或保存中的迟到回调。文稿持久化、版本和页序核对成功后才导航。

`ocrText` 可以修改，`ocrKey` 和 `ocrLanguage` 不因纠错而刷新。旧 OCR 仍失效；没有识别基线的手动文字仅供查看/复制。当前图像对应且已确认四角的已保存文字可用于现有应用搜索。公式和手写不能据此认为正确。

**人工纠正的文字目前不会进入可搜索 PDF。** 当前 PDF 路径重新识别图像生成文字层；编辑器和导出选项均明确说明。重新识别文稿也会替换已保存的 OCR 文字。

## 主机测试边界

使用已有完整 Python 3.10+ 和 JDK17+，从仓库根目录运行：

```sh
python3 -B tools/test_host.py
```

主机测试不联网、不安装依赖，输出保留在被 Git 忽略的 `build/` 目录。`ocr_review` 使用当前生产方法与真实 coordinator/journal，控件、Models 和 writer 是明确替身；其 28 场景/67 断言覆盖会话保护、文字当前性、失败保留及线程竞态。`draft_ui` 执行实际提取的恢复方法与策略，Models/JSON/渲染仍是替身。

源码预览验证使用已有 Java21 编译器；该镜像缺少 release17 平台资料，原始 release17 失败被保留，复核使用明确的 source/target17 模式。它不是 Java17 API 可用性验证。完整 JDK 环境应使用默认入口；没有下载或安装 JDK/SDK。

Android 构建、真实 `org.json`/Store/AtomicFile、IME、选区与焦点、实际快速切页和进程恢复、OCR 模型准确率、PDF 文字层及设备行为均未验收。需要在具备既有构建依赖的环境继续验证，不能用主机通过替代。

本次只包含原创源码、非私人合成测试与说明。Apache-2.0、现有第三方 notices 和固定依赖来源保持不变；不含用户材料、测试运行输出、模型、APK、密钥或构建缓存。构建缺口继续见 `DEVELOPMENT.md`、`OCR-DEPENDENCIES.json` 和仓库 README。
