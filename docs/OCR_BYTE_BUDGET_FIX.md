# OCR 纠错容量与恢复保护 · 源码开发预览

本修复基于逐页 OCR 编辑功能。当前候选未构建 APK，未验证 Android 构建、UI/生命周期、设备、原生 OCR 或 PDF；历史运行记录不是当前候选验收。仓库未新增模型、构建工具或外部运行依赖，原许可证和 notices 保留。

## 保存与失败处理

超长输入保留全文，不按字符数近似限长，也不静默截断。保存先冻结文稿/页面/会话，再在 worker 中检查实际序列化字节：

- `EditDraftStore.validate` 共用真正 WED 编码器，检查 UTF-8 无损性、单字段与整条 4 MiB 记录，包括基线、编辑 JSON、版本、时间、字段 framing 和校验和。
- `preflightEditorSave` 序列化完整候选文稿，仅替换准确目标页，计入其他页（包括移除页）、标题与元数据。以实际序列化的 `Long.MAX_VALUE` 为将来更新时间保留最长非负 long 表示的字节，不改变原文稿。
- 预检和真实 `Store.save` 共用 `manifestBytes` / `SerializedBudget.manifest`，按 `JSONObject.toString(2)` 输出的 UTF-8 字节执行 2 MiB 整本文稿上限，计入中文、emoji 和 JSON 转义。

预检或独立记录写入失败发生在文稿 writer 之前，仍留在完整可编辑草稿，可复制、明确返回/放弃或缩短重试。已进入文稿写入的失败保留独立记录，不假报成功。pending 和 busy 仍阻止输入漂移。旧未核实记录只有原版本/页面基线一致时才可回到草稿；这条内存状态检查不等于真实原图重新哈希，最终保存仍由磁盘版本 fence 保护。也可先保留完整生命周期快照、核对写入后明确离开。

## 生命周期与私有数据

新 saved-state 不再写出页面/OCR 原文。控件关闭自动文字状态保存，应用写入不可变私有 `edit-lifecycle` 文件并验证哈希/读回，状态只传固定形状的引用；普通恢复回执同样只写四个固定字段，即使后台加载交错也不会把原文重新放进 Bundle。Android 没有在这里被假设为一个固定通用的 Bundle 安全容量。

本应用生命周期文件策略为每条 16 MiB、每文稿 256 条/128 MiB，区别于 4 MiB 普通恢复记录和 2 MiB 文稿。文件不自动删除，**普通 ZIP 不包含生命周期快照**。文稿提供查找入口；暂时读取失败保留原回执，大快照与当前版本冲突会在文稿界面拒绝而不再进入阻塞恢复屏。

写盘失败明确报告且保留当前输入。进程内退路最多 8 槽、合计 16 MiB 实际 UTF-8 字段内容；替换/确认保存/明确放弃释放过期 token。满额不逐出其他仍持有的输入。内存退路不能跨进程死亡，磁盘/内存都不可用时无法保证重建后恢复；不会把未落盘内容称为已保存。

最终生命周期快照目前同步执行编码、写入、force 和读回，大草稿或慢存储可能产生主线程延迟。Android 时延、ANR、Bundle、任务移除和多 Activity 尚未验证。自动私有快照与放弃后仍保留的提示在界面明确显示。PDF 缓存 revision 使用 SHA-256，兼容旧原始 revision 的读取。


统一入口包括 26 个运行项；云端 source/target17 复核为 26 项通过、0 个平台分支跳过。新增预算/快照测试为 9 场景/47 断言，保存/恢复接线为 15 场景/62 断言，逐页 OCR 组为 28 场景/67 断言。运行项数不是场景总数。输出只在本地被 Git 忽略的 `build/` 中生成，不作为源码发布。

预算测试执行生产 codec、真实文件和第二个主机 JVM 读回；接线测试提取当前 MainActivity 保存、预检、恢复、生命周期 hook 和 `completeStartup`，编译真实 Models、mutations 和存储。JSON、Store writer、调度和控件是明确主机替身；JSON seam 不是 Android org.json，第二个 JVM 不是 Android 进程重建。独立审查发现的恢复封锁、失败引用丢失、内存累积、PDF revision 和回执交错问题均已补充针对测试。

云端已有 Java21 缺少 release17 平台资料，保留原始失败后以 source/target17 模式复核；不是 Java17 API 可用性检查。默认入口仍要求完整 JDK，源码不自带适配器、JDK、SDK/NDK/Gradle wrapper、OCR 模型、字体或 vendor 缓存。完整 Android 构建依赖与相对目录缺口继续见 `DEVELOPMENT.md` 和 `OCR-DEPENDENCIES.json`。不保证全新克隆可直接完成 Android 构建。

**人工纠正文字目前不会进入可搜索 PDF。** 当前只保存整页文字和图像 key，没有可维护的词/行位置映射。纯文字导出与 PDF 文字层同步是不同功能：前者可做带页码的 UTF-8 副本（尚未实现文件导出，当前可复制）；后者必须先设计并验证与图像版本绑定的位置数据、自由编辑后的重排及坐标变换。本候选不伪造坐标、不把未校对文本标为已校对，也不改变原图。界面继续如实提示 PDF 重新 OCR。
