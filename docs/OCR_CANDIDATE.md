# 单页重识别候选比较（源码开发预览）

基线为 PR #2 的 `5fee32b634071705a4c4d7bf8b5bf15e9e00018d`。现有编辑器已经提供图像与可编辑文字对照，横屏时并排显示；整本 OCR 会替换已保存文字。本代补充单页重识别与人工修订安全比较，不改变识别算法、模型或 PDF 文字层。

## 操作流程

在编辑页核对四角后，选择“单页重新识别 · 先比较，保留修订”，再选择中英混合或仅英文。识别使用当前草稿的图像处理参数与原有 2400 长边渲染。结果只是候选，原图、当前文字和已保存页面都不会自动改变。公式与手写仍需以图像为准；没有针对具体错字或样张的自动纠正。

比较窗口显示识别启动时的完整原修订和新候选，可选中文本、复制候选或保留原修订。候选为空时明确提示采用会清空文字。人工编辑、自动识别及旧版未知来源继续分开标记，不把自动候选标为人工校对。

选择“保留旧稿并采用候选”后，先核验原图及已保存版本、用生产序列化方法检查候选能否进入文稿，并向现有独立编辑恢复区保留完整旧草稿。容量、写入或核验失败时保持原文字可编辑，不进入阻塞编辑的恢复界面。成功后只把新文字、识别键、语言与自动来源放入当前草稿；仍需明确“保存本页”或“保存并下一页”。原保存失败／恢复／重试契约不变。

旧稿保留于文库“找回编辑恢复记录（含冲突稿）”，不会删除或自动重放。原版本仍一致时才能重新载入；保存新稿后旧稿通常会成为冲突记录，仍可查看参数或单独导出，不能直接覆盖新版本。普通 ZIP 不包含独立恢复区，既有每文稿 256 条／64 MiB、单条 4 MiB 的限额仍然适用；本代不删除旧记录或绕过限额。

单页候选仅在本次 Activity 内存中保留，不写 Bundle，也不承诺跨进程恢复。可通过“查看本次单页识别候选”重新比较。切页、会话、文稿、页序、图像参数、文字、已保存版本或生命周期变化会使候选过期；过期候选仅供明确查看／复制，不可采用到当前页面。识别失败可重新发起；旧修订不会被失败或迟到结果替换。采用旧候选的迟到确认不能消费较新的候选，重复采用不能重复覆盖。

可搜索 PDF 仍重新识别图片，不使用人工纠错文字或此候选的文字字符串。用户可继续将已保存文字或草稿另存为带页码 UTF-8 副本；[文件提供者及同步边界](TEXT_EXPORT.md)不变。

## 验证与环境限制

云端有 Tesseract CLI 5.5.0，但仅有 `eng`／`osd` 模型；没有项目校验过的中文模型、Android SDK、项目 JNI 运行环境或真机中文对照样本。旧测试目录中的模型文件是合成完整性测试材料，不是真实 OCR 资产。没有安装、下载或替换任何依赖，也没有借用 CLI 英文输出声称 Android 中文识别变好。

`tests/host/ocr_candidate.py` 执行提取的生产 `recognizePage`、MainActivity 来源确认／比较／采用回调、实际 OcrCandidate、Models、预检、EditDraftStore 文件与 RecoverySourceGate 原图哈希。原生 OCR、图像解码／渲染、Android 控件／剪贴板／调度、Store 写入和 JSON 为明确主机替身。原图核验使用合成字节，不是识别质量样本。

场景包括人工旧稿与未保存输入、当前图像参数、空候选、多字节中文／emoji／换行／公式、失败／取消和重试、迟到切页／文稿／页序／输入／图像／版本／生命周期、重复与新旧候选竞争、真实原图篡改、恢复写入失败、较大旧稿／候选的生产字节预检，以及采用后实际保存协调器的回滚和重试。集中入口为 `python3 -B tools/test_host.py`，所有材料均为合成数据。

最终集中运行 29 个检查条目全部通过、0 个记录的平台跳过，运行前后生产源码散列一致。新增候选组 22 场景／52 断言通过，并由两位独立审查者分别复跑。独立审查确认并修复了“最后一次读取后另一 Store 发布新版本，而旧对象未刷新仍能采用候选”的 P2：发布和采用同时匹配全局已观测版本，原探针复核不再替换旧修订，旧记录仍完整保留。41 个生产 Java 文件语法解析无错误。这些是主机证据，不是 Android 或 OCR 质量验收。

Android 编译、资源／DEX／链接、真实 UI／IME／对话框布局／剪贴板／生命周期／进程重建、原生 OCR／中文准确率、PDF 和设备未运行。JDK21 上的 Java17 源码／classfile 目标与语法解析不等于 Android 或 Java17 API 验收。原图核验是生产文件协议的主机验证，不是对任意外部进程并发修改的原子保证。
